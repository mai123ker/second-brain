# 关联规则（P1 机制，P0 只立校验桩）

> **派生说明**：依据《产品落地文档全集》§7 整理，非用户原件；原件到位请以原件替换。

## 不做脑图，做关系句

关键词同现建链会在 1000 条记录里长出几千条连线，那不是结构，是毛线。全局图谱可看不可判断，三天后变壁纸。

**采用：不产出图谱，只产出带理由的关系句。**

> 你 2026-08-03 写过「先不碰硬件，纯软件跑通再说」——和这条相反方向。

## 链接绝不写进 `.md`

1. 原文不可变；
2. `updated` 不得因程序变化；
3. 链接是易变数据，写进文件等于把易变的东西固化。

**所有关联只存 `.index/index.db`**，可删可重建，重建后链接变化是允许的。
（用户本人在正文里手写 Obsidian 双链属于原文，程序不得添加、删除或改写。）

## 三条收敛规则

1. **同目标**：只在同一 `target` 下建链，跨目标一律不做。
2. **每条最多 3 条**：上限即质量，第四名通常是噪音。
3. **必须带理由**：说不出为什么就不建。

## 允许的四种关系类型（封闭集合）

| TYPE | 含义 |
|---|---|
| `opposite` | 方向相反 |
| `same-thread` | 同线延续 |
| `premise-gone` | 一方前提被另一方否定 |
| `topic-drift` | 名义同题实际换对象 |

集合外的关联一律不建。**注意与卡片 `relation` 的区别**：卡片用的是 `conflict / complement / premise_unsatisfied / inconsistent`（见 §6），两套枚举不可混用。

## 悬空概念

随手写下、尚未成为目标的词进入待归位区，视为悬空概念；第二次出现时提示「这个概念你提过两次了，要不要建成一个目标」。目标建成后关联只写入索引库，不改原记录。
