# 形态变更说明（2026-11-11 用户拍板）

> 用户否掉了「四页表单应用 + 一条记录一个碎片 .md」的实现，明确要求：
> **一个主题 = 一篇长 Markdown 文档**，标题、段落、小标题、表格、`- [ ]` 待办都写在
> 同一篇里，用左侧文件树导航（参照 Obsidian 的文档视图）。
> 同时确认：**不做关系图谱**，沿用《全集》§7.1「不做脑图，只产带理由的关系句」。
>
> 本说明与 `开工总任务书.md` §4 / §9、`产品落地文档全集.md` §4 / §9 冲突时，
> **以本说明为准**（其余章节与红线继续有效）。原规格文件保持原样，未修改。

## 数据形态

```
records/                       ← 整棵文档树，Obsidian 直接打开
├── 目标/                      目标文档（kind=goal）
├── 人生阶段总结/
│   └── 岗位拆解/岗位笔记.md   一篇长文：# 岗位笔记、段落、## 小标题、表格、## 待办
├── 思考/
├── 学习/
├── 外部素材/                  外部流长文（frontmatter 带 source/stance/scope）
├── 待归位/                    未挂目标的文档
└── _v0_fragments/             上一版碎片记录归档，不参与索引与展示
cards/                         （历史留档）原对照卡片存档目录，2026-11-11 已随对照引擎移除，现行版本不建此目录
.index/index.db                仅作索引，删库可重建
```

- **一个主题一篇 `.md`**，文件名用语义化标题（如 `季度复盘.md`），重名追加 `-2`。
- frontmatter **15 字段**：`id/title/stream/kind/target/topic/version/confidence/status/created/updated/source/stance/scope/claim_relation`。
- 正文是完整 Markdown；`- [ ]` / `- [x]` 就是待办，勾选直接改写该行。
- 结论由用户点「已思考」后**追加到当前这篇文档**的 `## 结论 · v{n}` 区块，
  同时更新 frontmatter 的 `version` / `claim_relation`，不再新建碎片文件。

## 不变的红线

1. 程序不改写用户原文；只有用户主动编辑、勾选待办、提交结论才写回。
2. `id` / `stream` / `created` 永不可改；归位只改 `target` / `status`，且不动 `updated`。
3. 模型只产卡片，卡片存 `cards/*.md`，**不写进用户文档**。
4. 素材不足不调模型；`guard.py` 六类丢弃照旧；三种失败三种真话。
5. 链接不写进 `.md`，不做图谱、看板、CDN、远程字体、埋点。

## 接口

| 接口 | 说明 |
|---|---|
| `POST /records` | 新建一篇长文文档 |
| `GET /goals/{id}/context` | 从长文抽判断片段，sufficient 由代码判定 |
| `POST /compare` | 产卡片（独立存档），不写用户文档 |
| `POST /cards/{id}/thought` | 结论写回 `doc_id` 指定的当前文档 |
| `GET /docs/tree` | 左侧文件树 |
| `GET/PUT /docs/{id}` | 读整篇 / 保存整篇 Markdown |
| `POST /docs/{id}/todo` | `toggle` 勾选 / `add` 新增待办 |
| `GET /goals`、`GET /records`、`POST /records/{id}/place` | 文档列表与归位 |
